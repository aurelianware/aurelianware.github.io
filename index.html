The product

What Cloud Health Office does today.

Each line below links to published evidence. Everything is tested on synthetic data. No plan runs Cloud Health Office in production yet.

  1. 01

    Nine ONC Inferno kits pass

    US Core, CARIN Blue Button, Da Vinci Plan-Net, Bulk Data, Da Vinci PDex member match, Da Vinci CRD, DTR and PAS, and SMART App Launch run every night against the main branch on synthetic data. Passing a kit is not CMS or ONC certification. Nightly results

  2. 02

    CMS-0057-F APIs

    Patient Access, Provider Access, Payer-to-Payer, Provider Directory, and Prior Authorization FHIR APIs, with acceptance status published per API, gaps included. Compliance status

  3. 03

    A file drop beside QNXT and Facets

    Standard daily files load into CHO next to the existing core: CARIN CPCDS extracts, 834 enrollment, prior authorizations, and fee schedules. The core stays the system of record. Live core adapters are optional. Watch the two-minute demo

  4. 04

    CPCDS import and export

    Claims data moves in and out in the CARIN Common Payer Consumer Data Set format, the same shape the Patient Access API serves.

  5. 05

    Texas Medicaid rules

    APR-DRG inpatient pricing from HHSC tables, EAPG outpatient pricing, encounter submission with 999 and 277CA reconciliation, and Texas UMCM reports. Texas compliance

  6. 06

    Source you can read

    The full platform is on GitHub under BSL 1.1, so a plan’s security team can review the code before it signs. Source

Business model

A software subscription, not billable hours.

Revenue

Subscription license

Health plans pay an annual Cloud Health Office license, priced per member per month and sized to the plan. Plans enter at the Foothold layer and expand to Domain cutover and Core on their own timeline.

Supporting

Implementation and onboarding

Each new plan gets help standing up its file drop, its APIs, and its first tenant. That work exists to start a subscription. We do not sell staff time on its own.

Cloud Health Office is licensed under BSL 1.1. Anyone can read and evaluate the source. Production use requires a commercial license from Aurelianware, Inc. More on the model
